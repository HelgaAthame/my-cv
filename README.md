# my-cv

Olga's CV and portfolio — a statically exported Next.js site published to
GitHub Pages.

**Live:** [helgaathame.github.io/my-cv/hr-cv](https://helgaathame.github.io/my-cv/hr-cv)

## The two pages

| Route | What it is |
|---|---|
| `/hr-cv` | The CV proper. Hero with four provable numbers, projects in a bento layout with screenshots, experience, skills, education. Prints to a clean one-file PDF. |
| `/hr-cv/projects/[slug]` | A case study per featured project — what the problem was, which trade-off was taken, and why. Generated from `src/data/projects.ts`. |
| `/` | The older interactive portfolio: animated background, skill tables, project links. |

## Running it

```bash
npm install
npm run dev     # http://localhost:3000/hr-cv
npm run build   # static export into ./out
npm run lint
```

`next.config.mjs` sets `output: "export"`, so there is no server at runtime;
`basePath` is `/my-cv` in production only, because GitHub Pages serves the
site from a subdirectory.

## How it deploys

`.github/workflows/nextjs-new.yml` builds on every push to `main` and
publishes `./out` to GitHub Pages.

> `.github/workflows/nextjs.yml` is a leftover from before the branch was
> renamed — it triggers on `master`, which no longer exists, so it never
> runs. It should be deleted.

## Decisions worth knowing before editing

**Projects live in one place.** `src/data/projects.ts` is the source for the
bento tiles, the case-study pages and their `generateStaticParams`. Adding a
project means adding an entry there, nothing else.

**Colors go through CSS variables, never Tailwind color utilities.** The page
has a dark and a light theme plus a print stylesheet, and `text-white` cannot
be re-pointed at dark ink for the light theme without an `!important`
sledgehammer — `--title` can. Use the semantic classes (`t-title`, `t-body`,
`t-muted`, `t-accent`, `surface`, `chip`, `hairline`) defined at the top of
`src/app/hr-cv/globals.css`. Print re-declares the light tokens in one block,
so paper and the light theme cannot drift apart.

**The theme toggle holds no React state.** Both icons are always rendered and
CSS hides the wrong one; the initial value is applied by an inline script in
`src/app/hr-cv/layout.tsx` before first paint. This page has been bitten by
hydration mismatches before — see below — and a `useState` holding the theme
would either hydrate wrong or need a mounted-flag dance.

**Nothing random at render time.** The striped background is generated by a
seeded PRNG (`mulberry32`), not `Math.random()`, because module scope runs on
both the server and the client during static export and a real random source
produces different markup on each. `StarBackground` and `ParallaxBackground`
both hit exactly that bug once already.

**`/hr-cv` is its own root layout.** The main site lives in the
`src/app/(main)/` route group with a separate root layout, because a nested
second `<html>`/`<body>` broke hydration.

## Layout

```
src/
  app/
    (main)/            older interactive portfolio
    hr-cv/             the CV: layout, globals.css, page
      projects/[slug]/ case-study pages
  components/
    hr-cv/             Hero, ProjectsBento, ThemeToggle, HrCV
    content/           components of the interactive page
  data/projects.ts     single source of truth for projects
public/shots/          project screenshots (webp, 1200px wide)
plan.md                running work log — read it before starting anything
```
